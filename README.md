## 下载安装

到 [**Releases**](https://github.com/HONYUZHE/spark-helper/releases/latest) 下载最新的
`火花助手-vX.Y.Z.apk`（54 KB，Android 6.0+），传到手机上点安装即可。

- **别在微信里直接点开安装包**，微信会拦；先「保存到手机」，再从文件管理器点。
- 文件管理器里找不到时，**别用「下载」分类**（它查的是 MediaStore），走「内部存储 → Download」。
- 装完请读 [使用说明](使用说明.md)：必须开无障碍、关电池优化、开常驻保活，**并且先用「试运行」验证**。

## 这是什么

一个**不需要 root、不需要电脑、不联网**的安卓小程序：每天在你设定的时间，自动打开抖音、进入和某个好友的聊天、输入并发送一条消息，用来维持聊天火花（连续聊天标识）。

- APK 只有 **50 KB**，零第三方依赖，Android 6.0+（API 23+）
- **没有申请 `INTERNET` 权限** —— 物理上无法联网，也就无法上传任何东西
- 无障碍服务只监听**抖音的两个包名**（`com.ss.android.ugc.aweme` / `.lite`），看不到你其它 App 的内容
- 发送的消息内容会做校验，且每次跑完都把经过写进日志，出问题能定位到具体哪一步

> ⚠️ 抖音的用户协议不允许自动化操作。本工具只在你自己的手机上、给你自己的好友发消息，请保持低频（一天一条），消息内容尽量像人话，并自行承担账号风险。程序内置「试运行」模式：**只走流程不点发送**，可以先用它确认没问题。

## 一、装到别的手机上

1. 把这个 APK 用微信 / QQ / 数据线 / 蓝牙传到对方手机（别用微信直接点开安装，微信会拦；**先保存到文件，再从文件管理器点**）。
2. 手机可能提示「不允许安装未知应用」→ 点提示里的**设置**，把当前这个应用（文件管理器 / 浏览器）的「允许安装未知应用」打开，再回去点安装。
3. Android 8 以上要在「设置 → 应用 → 特殊权限 → 安装未知应用」里给对应来源授权。

APK 是自签名的（key 见 `spark.keystore`，口令 `spark123456`）。以后要覆盖升级，**必须用同一个 keystore 签名**，否则系统会报「应用未安装」。

## 二、第一次配置（每台手机都要做一次）

打开「火花助手」，界面顶部是一块状态区，**点它**会弹出逐项处理的菜单：

| 项 | 为什么必须做 |
|---|---|
| ① 无障碍服务 | 必做。没有它程序无法操作抖音。在系统列表里找到「火花助手」打开 |
| ② 关掉电池优化 | 强烈建议。否则定时会被系统推迟甚至取消 |
| ③ 允许精确闹钟 | 建议。不允许时会退化成不精确闹钟 + 30 分钟心跳补跑，可能晚几分钟到一小时 |
| ④ 自启动 / 后台弹出界面 | 国产 ROM 必做，见下一节 |

然后「＋ 添加任务」：

- **对方名字**：必须和抖音消息列表里显示的**完全一致**（昵称或你给他的备注名）。默认只要"包含"就算匹配，勾上「名字必须完全一致」更严格。
- **消息内容**：可以写多条，用 `|` 隔开（例：`在吗|打卡|早`），每次随机挑一条发，降低被判定成机器人的概率。
- **时间**：建议设在你**通常正在玩手机**的时间（比如 20:30）。原因是——**手机锁屏且有密码/指纹时，程序没法自己解锁**，只能上滑解开无密码的锁屏。

## 三、国产 ROM 的自启动设置（漏了这步定时多半不生效）

| 品牌 | 位置 |
|---|---|
| 小米 / 红米 | 设置 → 应用设置 → 应用管理 → 火花助手 → **自启动** 打开；省电策略选「无限制」；最近任务里给应用**加锁** |
| 华为 / 荣耀 | 设置 → 应用 → 应用启动管理 → 火花助手 → 手动管理 → 三个开关全开 |
| OPPO / realme / 一加 | 设置 → 电池 → 应用耗电管理 → 火花助手 → 允许后台运行 / 允许自启动 |
| vivo / iQOO | 设置 → 电池 → 后台耗电管理 → 火花助手 → 允许后台高耗电；i管家 → 自启动管理里放行 |
| 三星 | 设置 → 电池 → 后台使用限制 → 从「休眠应用」里移除 |
| 原生 Android | 设置 → 应用 → 火花助手 → 电池 → 不受限制 |

## 四、先试运行，再等定时

任务卡片上有两个按钮：

- **试运行**（推荐第一次一定点）：会真的打开抖音、走进聊天、把消息打好，但**不会点发送**。跑完回到 App 看「运行日志」。
- **立即发送**：真的发一条。

日志里如果出现 `失败：...`，后面会附带**当时的界面快照**（抖音那一屏所有有文字的控件）。把日志复制出来发给作者，就能定位是哪个控件对不上。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 日志说「无障碍服务没有开启」 | 去系统设置里打开，或从顶部状态区点① |
| 日志说「手机锁屏且设置了密码」 | 把时间改到你正在用手机的时段，或临时取消锁屏密码 |
| 日志说「消息列表里没找到 XXX」 | 名字和抖音里显示的不一致；或该会话沉到列表太靠下了 |
| 日志说「找不到发送按钮」 | 抖音改版了。把日志发给作者更新选择器；同时可先用「试运行」看快照 |
| 到点了没反应 | 多半被 ROM 杀了后台，照第三节配一遍；再看「运行日志」有没有记录 |
| 发了但没确认到 | 日志会写「已发送（未确认）」，通常是读取时机太快，一般消息已经发出去了 |

## 六、状态区怎么理解

```
✅ 无障碍服务：已开启          ← 不开就用不了
✅ 电池优化：已忽略            ← 建议忽略，否则容易被推迟
✅ 精确闹钟：可用              ← 不可用时靠心跳补跑兜底
✅ 抖音：已安装
⏰ 下一次执行：09-18 20:30
```

# 从源码构建

不需要 Gradle / Android Studio —— 这套手工链路在 **arm64 安卓手机上都能直接跑**（官方 build-tools 只有 x86_64，Gradle+AGP 在手机里跑不起来）。

```bash
./build.sh            # 产物在 out/spark-helper-v1.0.4.apk
```

依赖：`openjdk-17+`、`aapt`、`apksigner`、`zipalign`（Debian/Ubuntu 上 `apt install aapt apksigner zipalign openjdk-17-jdk-headless`）、`r8.jar`（脚本会从 Google Maven 取，或复用已有的）。

构建链路：`aapt v1 生成 R.java → javac -source 8 → R8/D8 出 dex → aapt 打包 → zipalign → apksigner 签名`。

> 注意：`aapt v1` 解析不了 API 33+ 的 `resources.arsc`，所以脚本会在 `platform-30/32/35` 里逐个实测，选一个能用的（实测 API 32 可用）。

## 代码结构

```
proj/java/com/dsha/spark/
├── MainActivity.java    配置界面（全部用代码搭 UI，无 XML 布局）
├── SparkService.java    无障碍服务：常驻、任务排队，同一时刻只跑一个
├── Engine.java          核心状态机：亮屏→启动抖音→关弹窗→消息页→找好友→输入→发送→校验
├── Ui.java              无障碍底层封装（查找/点击/手势/输入/界面快照）
├── RunService.java      前台服务：通知栏显示进度，防止跑一半被系统回收
├── Scheduler.java       每日闹钟 + 30 分钟心跳补跑
├── AlarmReceiver.java   闹钟触发、漏跑的补跑判定
├── BootReceiver.java    开机/更新后重排闹钟
├── Store.java           任务与日志持久化（SharedPreferences + JSON）
├── Task.java            任务模型
└── Notify.java          通知
```

设计上刻意做了三件事：

1. **轮询而不是事件驱动**：抖音的控件树在动画期间会反复失效，基于 `onAccessibilityEvent` 的状态机会被噪音打断。
2. **每个控件都有多个候选 + 坐标兜底**：文字找不到就找 `contentDescription`，控件不可点就用祖先，祖先也不行就用 `dispatchGesture` 点坐标。
3. **失败必留证据**：任何一步失败都会把当时的界面快照写进日志，而不是只抛一句「失败」。

## 真机校准记录

在一台 Android 16、3200×2000 横屏的平板上实测抖音，取到的真实控件结构和踩到的坑：

| 控件 | 真机实测 | 对代码的影响 |
|---|---|---|
| 底部「消息」标签 | 可点击容器 `[1760,1840,2080,1962]` 里套一个文字节点 `消息 (1920,1900)` | 要按文字找到后，**点它的可点击祖先** |
| 进入消息页后 | 「消息」文字节点的位置会从 `(1920,1900)` **跳到页面标题 `(1600,153)`** | 只能用底部标签来"进入"，不能用它判断"已在消息页" |
| 会话行 | 两套节点：可点击整行 `[0,1069,3200,1249]`，文字是 `名字,预览`；另有独立的名字 TextView `[40,1089,180,1229]`，**只有 140px 宽** | ❌ 用宽度过滤候选会把精确匹配的名字节点筛掉；改成**按匹配度打分**，再往上找整行来点 |
| 消息页特征 | 顶部「在线」好友头像条 + `新关注我的` / `互动消息` 两行 | `looksLikeMessageList()` 按这些字样判断，别用臆想的「新朋友」 |
| 发送按钮 | `发送`，可点击，`(3102,1882)` | 精确文字「发送」+ 下半屏，命中 |
| 表情面板 | 打开时底部出现 `搜索相关表情包`，且**那也是个输入框** | 输入框查找必须排除「搜索」类节点，并先按返回键收起面板，否则会把消息写进表情搜索框 |

> 结论：写这类自动化，**必须真机取一遍控件结构**。光靠想象写出来的选择器，在「名字节点只有 140px 宽」这种细节上就会翻车。

## 真机跑出来的坑（v1.0.1 → v1.0.3）

装上真跑之后暴露的问题，全部是靠**失败时留下的界面快照**定位的，记在这里避免重复踩：

| 症状 | 真正的根因 | 修法 |
|---|---|---|
| 一点「立即发送」就报「没找到抖音」，可状态区明明显示已安装 | 用 `getLaunchIntentForPackage()` 当"装没装"的判据，它在本机 Android 16 上装了也返回 null，而同一进程里 `getPackageInfo()` 是好的 | 安装判据改用 `getPackageInfo`；启动改成显式 `ComponentName`，并申请 `QUERY_ALL_PACKAGES` |
| 同一个版本，一次 `launchIntent=有`，下一次 `null`，白等 30 秒超时 | 包可见性会飘；而隐式启动在拿不到解析结果时不会抛异常，只是"什么都没发生" | 启动后等待失败就**换策略重试一次**（先回桌面再启），而不是干等 |
| 报「消息列表里没找到 XXX」，但快照抓到的是**个人主页** | 消息页有 `互动消息,XXX 在评论中提到了你` 这种行，文字**包含**好友名字；用"包含即匹配"会点中它，跳进互动页/主页 | 只认三种候选：整段文字就是名字 / 抖音会话行格式 `名字,预览` / 不含逗号的独立昵称控件；并加通知行前缀黑名单 |
| 界面残留在个人主页时，会点到完全不相干的东西 | 抖音会恢复上次停留的页面；而「底部消息标签」曾有个"退而取整棵树里位置最低的那个消息"的兜底，在主页上会命中错误目标 | 去掉那个兜底；新增 `ensureMainPage()`：先用返回键退回有「首页/朋友/消息/我」的主界面，退不动就回桌面重启抖音 |
| 排查全靠猜 | — | 每一步的关键判定（匹配到哪个节点、启动用了什么入口、包可见性诊断）都写进日志；失败必附当时界面快照 |
| 用两下就提示「要打开无障碍」，可无障碍在设置里明明是开着的 | **不是无障碍被关了，是 App 进程被系统回收**：进程一死无障碍就断开，系统几秒后自动重连；而旧逻辑"等 15 秒找不到服务就报错"正好卡在这个空窗期，且报的话是误导 | ① 找不到服务不再直接报错：把请求**挂起**，最多再等 90 秒，重连上来由 `SparkService.onServiceConnected()` 领取补跑（`Store.PendingRun`）；② 报错文案区分「设置里没开」和「开着的但连不上」；③ 新增常驻前台服务保活（IMPORTANCE_MIN 静默通知），减少进程被回收的概率；④ 注册 `Application`，每次进程启动/无障碍解绑/销毁都写日志，并装全局未捕获异常处理器把崩溃落盘——"无声消失"变成可查 |

> 这几条的共同点：**失败时留下的证据**比任何猜测都值钱。日志里那句
> `18:36:37 [FAIL] 无障碍服务没有开启` 后面紧跟着 `18:36:55 [OK] 无障碍服务已连接`，
> 一秒后就自己连上了 —— 就凭这两行的先后顺序，才能断定"无障碍其实一直是开的"。

## 反馈问题

最有用的是日志：App 里点「导出到 Download」，然后把 `Download/火花助手日志.txt` 提交到
[Issues](https://github.com/HONYUZHE/spark-helper/issues)。日志里含每一步的判定结果，
以及出错那一刻的抖音界面快照 —— 光凭这两样基本就能定位问题。
